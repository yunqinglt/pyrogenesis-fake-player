# 数学地形与个人策略持久化方案

记录日期：2026-11-05；2026-11-06 补充；2026-11-07 更新实现状态。`analyze_terrain_region` 已实现紧凑、视野受限的高度／坡度与建筑占地采样摘要；本方案中更高级的路径、通行性与优化选址仍属后续方向。独立只读存档分析器已实现，见 [save-analysis.md](save-analysis.md)。未增加 NumPy/SciPy 依赖、自动案例记录器或策略训练流程。

## 数学地形可以做什么

在现有公平观察上增加 Python 计算层是可行的：

```text
MCP 允许的地形／对象观察
  → 带未知掩码、真实坐标、时间戳的网格
  → 局部坡度、距离、候选路线和建筑位置评分
  → 普通游戏命令
  → 观察实际结果
```

| 需求 | 可考虑的计算 | 结果的实际含义 |
| --- | --- | --- |
| 判断已知区域的起伏 | NumPy 数组与局部差分；坡度约为 atan(sqrt((∂h/∂x)²+(∂h/∂z)²)) | 采样分辨率下的局部估计 |
| 减少采集往返 | 到已知资源、存放点和道路候选点的距离／图路径 | 有助于比较位置，不等于实际工人往返时间 |
| 预留建筑周围空间 | SciPy 距离变换结合已知对象位置和公开尺寸 | 对已知障碍的近似余量，不能证明放置合法 |
| 比较行军路线 | 在已知区域建立稀疏图，以距离、坡度、可见威胁和信息陈旧程度赋代价 | 候选规划路线，需要原生寻路验证 |
| 寻找入口／狭窄区域 | 对已知空间做连通与宽度分析 | 只描述已知网格，不保证不存在未观察的出口 |

计算时使用返回的真实 x/z 及高度单位，不能把格子下标当作世界坐标。区域边缘可能有不完整格子，不能在所有位置一律假设相邻采样中心间距相同。地图当前最大 4096 个采样点也不适合构建大型稠密全点对路径矩阵；优先按任务查询局部区域和少量起终点。

必须保留三类信息：实际观察值、未知掩码、最后观察时间。未知高度不能填 0；缺邻点处不生成可靠坡度；插值不能变成对隐藏地形的事实声明。可把探索当作单独任务，但不能把穿过未知区域的规划称为已验证路线。

现有 MCP 提供中心点高度、水面和可见／历史对象，没有完整的游戏碰撞体、单位通行类别、道路宽度或建造位置预检。即使坡度低、空间评分高，位置仍可能因领土、单位阻挡、特殊距离限制等失败。地形计算层不应改写原生判断，也不应额外读取整张地图文件来补齐未知区域。

后续实现可将 NumPy／SciPy 设为可选依赖。先比较“失败放置次数”“实际到达时间”“采集者实际往返距离”等指标，确认收益后再增加复杂度。

## 至少保存多少残局

没有能保证模型掌握个人打法的统一最低数目。更合适的统计单位是**一次有上下文、有选择、有结果的决策案例**，而不是一帧画面或一个存档。

如果目标是让其他模型遵循个人偏好，先保存策略手册和案例库，按局势检索阅读。模型不会因为文件存在就自动永久学习；后续任务需要实际加载手册／相关案例，或者另行建立经过评测的训练流程。

建议首批目标为 **50 组标注案例：约 40 组示范、10 组独立盲测**。这是本项目的工程起点建议，不是论文给出的样本量下限，也不要求打满 50 局。同一局可以贡献多组决策，但不能把相邻帧计为彼此独立的案例。

示范案例可按八类各收集约五组：

1. 建筑布局与通道。
2. 采集分工与经济补缺。
3. 人口、出兵与生产队列。
4. 阶段升级及前置建筑选择。
5. 科技与互斥分支取舍。
6. 侦察、迷雾和信息不足时的选择。
7. 兵种搭配、保护经济与反制。
8. 攻城、驻军、撤退和止损。

每类尽量覆盖不同地图、文明、资源条件与顺逆风。训练／检索示范和盲测应按整局、地图／种子分组隔离；同一局相邻时刻不能分到两边，不能让盲测答案进入模型读取的案例库。

随后优先补充“模型实际走到某个局势 → 用户纠正 → 重新验证结果”的案例，逐步积累至 100–300 组，再根据盲测表现决定扩充方向。若要训练模型权重或独立策略网络，需要用学习曲线与独立评测确定数据量；上述 50／100–300 不能当作训练充分性的承诺。

## 怎么保存

建议把简短的个人规则与可复现案例分开：

```text
strategy/
  rules.md
  index.jsonl
  cases/<case_id>/
    manifest.json
    observations.jsonl
    decisions.jsonl
    actions.jsonl
    outcomes.json
    notes.md
    reproduction/
      replay/
        commands.txt
        metadata.json
      savegame/             # 游戏正常提供的存档，可选
```

`rules.md` 保存优先级、取舍与例外，例如“被骑兵袭扰时优先保住平民”“准备都市化前保留石料／金属”“什么情况下允许牺牲前置基地”。规则宜能落到可观察条件与动作，避免只写“重视经济”等无法判定是否遵守的口号。

案例也应记录半自动化分工：当时的高层负责人、姿态、已提交目标、自动续作与中断条件。将“模型实际发出的工具命令”与“观察到的单位 AI 交货／追击／续作”分开；不能把自动行为伪造成模型调用。只知道状态变化而无法确定原因时标为待确认，原生协作规则见 [MCP 手册](../MCP.md#半自动化协作规则)。

后续案例约定是人与游戏 AI、45 分钟停战、`conquest_units`（仅非动物单位，建筑不计）；视野为未探索迷雾、已探索迷雾或全图公开。规范保存在 [analysis_rules.json](../analysis_rules.json)。分析器分别输出预期与实际设置，不修改原档。将 `report.json` 和 `map.html` 放在案例的离线复盘资料中，并保留 `offline-save-omniscient` 标签；它们不是当时的玩家观察，也不能代替手写的选择、理由、预期与结果。

| 文件 | 最少应包含 |
| --- | --- |
| `manifest.json` | 游戏／模组／MCP 版本，地图与种子、文明、玩家席位、房间规则、目标、案例起止游戏时间、示范／盲测分组；确实不知道的值留空 |
| `observations.jsonl` | 决策前一段时间内的正常玩家观察、地图请求区域、可见性与 last_seen；建议先保留前 30–120 秒，并按决策所需调整 |
| `decisions.jsonl` | 当时的目标、可见依据、选择的动作、替代方案、简短理由和用户纠正 |
| `actions.jsonl` | 原始工具请求、返回、提交／确认时间；保留 accepted 与实际完成之间的区别 |
| `outcomes.json` | 指定时间窗口后的人口／资源变化、伤亡、队列、位置与局部任务结果；整局胜负作为补充 |
| `index.jsonl` | 可检索摘要：决策类型、文明、阶段、威胁、资源瓶颈、用户偏好和案例路径 |
| `reproduction/` | 对应版本的正常回放／存档，便于重新跑局面；不能直接作为公平对战模型的当前观察 |

可以先人工记录以下结构；本轮没有实现自动写入器：

```json
{
  "case_id": "han-minister-choice-001",
  "decision_type": "paired_research",
  "game_time_ms": 900000,
  "actor": {"observed_id": 301, "template": "structures/han/ministry", "role": "minister_producer"},
  "goal": "提高在暴露经济区活动的大臣生存能力",
  "visible_evidence": ["已有足够大臣", "侦察到敌方骑兵接近经济区"],
  "chosen": {"tool": "research_technology", "arguments": {"building_id": 301, "technology": "civil_service_02"}},
  "alternative": "civil_service_01",
  "reason": "当前补员速度不是瓶颈，优先考虑生命值",
  "label_source": "user_demonstration",
  "outcome_ref": "outcomes.json",
  "split_group": "match-001"
}
```

示例中的 ID、时间和判断不代表真实对局记录。历史工具日志保留原始 ID 便于复核；复用策略时应通过模板、角色、位置和当前观察重新选择实体，不能重放跨对局失效的 ID。

静态残局快照缺少“之前看见过什么、为什么走到这里”的信息；回放则可能包含所有玩家的命令和赛后全局摘要。因此保留二者，但只把当时允许的玩家观察及其历史提供给正在决策的模型。将事后全局分析、人工解释和反事实分开标记，避免让模型学会使用当时尚不可知的信息。

当前 MCP 控制台已经可以保存受限工具的完整请求／响应与延迟，但不会自动保存用户操作、人工理由或完整回放。当前启动参数中还有 `-autostart-disable-replay`，因此不能假设受控客户端已经录下回放；需要使用房主已有的正常回放，或在另行实现记录方案时明确调整该设置。不能为了补日志读取对手私有状态。

## 原始资料

以下公开资料经只读核对；50 组起步等数量是上文的工程建议，不来自这些文献。

- SciPy `distance_transform_edt`：精确欧氏距离变换支持指定实际采样间距。
- SciPy `sparse.csgraph.shortest_path`：图最短路可返回前驱；有稠密与稀疏算法的复杂度差异。
- Ross、Gordon、Bagnell（2011），*A Reduction of Imitation Learning and Structured Prediction to No-Regret Online Learning*：序列动作会改变后续观察分布，支持优先采集模型自身失误后的纠正案例这一方向。

```text
https://docs.scipy.org/doc/scipy/reference/generated/scipy.ndimage.distance_transform_edt.html
https://docs.scipy.org/doc/scipy/reference/generated/scipy.sparse.csgraph.shortest_path.html
https://proceedings.mlr.press/v15/ross11a.html
```

本地回放文件名可见 `_0ad-src/source/ps/Replay.cpp`；该源码与安装版存在提交差异，存档／回放的实际兼容性仍以对应游戏版本验证为准。
