## 原因与修复

两个 Windows 游戏实例读取同一份安装包时，第二个实例报基础资源缺失。Windows ZIP 读取路径使用拒绝共享读取的文件句柄；为主机提供独立 ZIP 副本后，原安装目录的受控客户端正常加载。`engine.prepare_host_runtime` 缓存独立主机目录，资源包物理复制，其他文件优先硬链接；原安装目录不作修改。

本地 `_0ad-src` 目录的提交与安装版本不同。检查本机安装包 `public.zip` 的 `autostart/cmd_line_args.js`、`autostart_client.js` 和 `autostart_host.js` 后确认，安装版本支持 `-autostart-port`，最终保留原参数，无需改写游戏的自动启动脚本。

联机 `ready` 现在要求 Python 中继已连接。真实游戏演示还要求双向转发计数都大于零，防止客户端绕过中继直接连接主机时误报验证成功。中继保持延迟创建上游连接，补充转发 ENet 连接数据及客户端断开原因的行为。
