# 靠近资源建仓库

输入树林／矿产的 `resource_ids` 或大致区域；可选 `builder_ids`、限定市政中心 ID、最多尝试次数（默认 3）。资源不明确时先观察用户指定区域，选择一个当地资源簇并说明。林场在这里指采木资源区，不假定存在名为“林场”的建筑。

本技能使用已连接的普通玩家 MCP：`player_status`、`observe_player`、`observe_map_region`、`describe_options`、`order_units`。动态信息只来自这些公开响应；不读存档、引擎快照或隐藏对象。没有建造位置预检、建筑精确碰撞盒和精确通行网格，以下流程选择候选点，最终合法性由游戏判断。

1. 确认 `ready=true`，取得当前己方观察和目标区域的地图。只用 `currently_visible=true` 的资源对象判断当前资源量、占用与风险；迷雾中的静态记录仅用于导航去重新观察，不当作现况。资源字段为 `resource.type`，按 `wood.*`、`stone.*`、`metal.*` 分组；树木也可由 `kind="tree"` 识别。地图 `truncated=true` 时缩小区域，避免把遗漏区域判为空地。
2. 从己方单位的 `properties.construction.templates` 找到该文明实际仓库模板，通常形如 `structures/<civ>/storehouse`，再以该建造者 `describe_options(kind="construction",ids=[模板])` 核对成本、阶段和存放用途。不能从旧对局文明拼出模板后直接建造。现有己方对象的 `properties.storage.accepts` 可判断哪些仓库、市政中心或移动存放点已能接收目标资源。
3. 先比较现有存放点：若已有合适存放点贴近资源、没有明显绕行，报告可以复用，不重复建仓库。若用户明确要求新建则继续。选择当地一组资源的工作边缘，尽量靠近采集者与主要采集面；不要将建筑压在矿点／树木中心或封住采集者通道。多资源簇按实际采集人数和往返距离考虑，不一律贴最近单棵树。
4. 在该资源簇面向己方安全区域的一侧选择数个候选位置。比较可见建筑／资源占位、已探索的地面高度与水面，给出足够建筑间隔和出入口空间。坐标应在地图内；默认保持同一基地与本轮资源区，不因放置失败跨基地。`placement.territory`／`distance` 只能说明规则，当前工具没有精确领土边界，靠近市政中心也不能证明位置合法。
5. 选最近的可建造者，优先真正空闲、未驻军且有世界位置的己方工人。默认不抽走正在采集、修理、守卫或战斗的单位；若用户指定忙碌建造者或明确要求调工，则记录原职责后换派。检查 `activity.idle`、`current_target` 和 `packing`，别用总空闲人数猜 ID。
6. 一次只提交一个候选位置的 `order_units`：`{"entity_ids":[建造者ID],"orders":[{"type":"build","template":"实际仓库模板","x":坐标,"z":坐标,"angle":0}],"queued":false}`。`accepted=true` 不证明已放置。等待游戏时间前进，检查计分板 `construction` 与附近实体是否出现对应地基；出现后追踪该地基，不重复建造。合法地基可能尚无施工者，先看建造者目标和路径，必要时对同一地基追加协助 `repair`。
7. 确认没有新地基、没有延迟任务且放置确实失败，才用下一个候选点重试；默认最多 3 个不同位置。超时／观察未更新时先观察，不盲目重发。达到上限则停止并报告当前位置限制。全程只建本次要求的一座仓库。
8. 完工可能换实体 ID。观察新仓库 `building.foundation=null`、`storage.accepts`、位置和建造者当前目标。原生建造有自动续作；若它们已经正常采集目标资源，不重复下令。用户要求建完后采集时，使用当前可见资源的真实 ID 设置 `gather` 并确认任务和背包；用户只要求建仓库时，不自行扩建或改派其他采集者。

报告仓库 ID／位置、服务的资源簇、施工状态及人员去向。距离采用直线估算；实际采集改善要看寻路、交货和资源库存变化，不能仅由“距离更近”宣称产能已提升。
