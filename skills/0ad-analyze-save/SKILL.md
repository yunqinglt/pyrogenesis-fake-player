# 残局分析与策略复盘

输入一个或多个用户指定的 `.0adsave` 路径、新的输出目录，以及可选的焦点玩家 ID、公开游戏模板路径和案例规则 JSON。使用 Python 3.11+；本技能的解析器仅依赖标准库，不需要 MCP、游戏进程或联网。

这是离线全知分析，所有结果标为 `offline-save-omniscient`。`--player` 仅改变报告焦点，仍保留其他玩家数据，不恢复迷雾。即使存档开启迷雾，也不能将报告当作当时玩家可见的信息或正在公平对战时的观察。收到在线操作请求时使用普通玩家 MCP；不要为了补齐视野而读取存档。

## 生成报告

1. 确认存档属于用户要求的复盘范围。先辨认玩家、文明、地图与保存时间；未给 `--player` 时采用存档中的玩家 ID，不假定模型或人类永远是玩家 1 或 2。
2. 从本技能目录运行 [scripts/analyze_save.py](scripts/analyze_save.py)，脚本路径按技能实际安装位置解析，与当前工作目录无关。每份存档使用不同且尚不存在的输出目录。Windows 可用 `python`，Linux 可用 `python3`。

   ```text
   python "<技能目录>/scripts/analyze_save.py" "<存档路径>.0adsave" --output "<新报告目录>" --player 1 --templates "<0.28.0公开模组目录或public.zip>"
   ```

3. 公开 XML 模板参与二进制解码，必须与存档版本及其模组一致。Windows 可自动发现标准安装；Linux 建议显式提供实际 public 目录，例如 `--templates /usr/share/0ad/data/mods/public`。额外模组重复传入 `--templates`，从低到高覆盖；不要混用其他版本的源码模板。工具不附带游戏资源。
4. 工具生成 `report.json`、中文 `report.md` 和自包含 `map.html`。先检查 JSON 的 `parse.complete`、已消费／总字节数、`warnings`、`template_context` 和各玩家 `class_count_check`，再做策略解释。输出已存在时换新目录；缺模板、版本不符或未知序列化格式时保留错误，不猜数据或输出部分成功报告。

分发的技能包已携带解析器。源码工作区中的技能入口复用项目 `src/pyrogenesis_analysis`；迁移时使用构建后的 player-kit 或 skill-kit 中的完整技能目录，不要只复制入口文档。

## 分析与比较

解读字段和统计口径前，读取 [references/report-guide.md](references/report-guide.md)。按用户的问题选取证据，不必每次罗列全表：

- 经济与市政：资源库存、实际采集人数、人口、平民／公民兵分工、空闲人员、生产和研究队列。Worker 与军队身份可能重叠，不能简单相加。
- 布局与防御：用实体坐标与对象图核对住宅、农田、生产建筑、城防和治疗支援的相对关系。先说明前线参照物，再描述前后；地图上方不自动等于前线。对象图不包含完整地形、通行网格或领土边界。
- 军事与科技：兵种和驻军构成、英雄和祭司分布、已研究科技、当前订单、攻城器折叠状态。静态模板名称不代表科技修正后的战斗数值。
- 规则核对：默认预期为人与 AI、45 分钟停战、清空敌方 `Unit+!Animal`，建筑不计入；允许未探索迷雾、已探索迷雾和全图公开。以 `rules_audit.actual` 为该存档事实，保留与预期的差异。用户明确提供其他规则时通过 `--rules` 指定，不更改存档来消除差异。

比较多个存档时，先按来源 SHA-256、`match_id`、地图和游戏时间确认是同局不同阶段还是不同对局。实体 ID 只在对应存档内有效。分别给出每份证据，再归纳共同倾向及反例；两个独立残局不能拼成一条行动时间线。

结论区分“快照直接事实”“支持的策略倾向”“仍需验证的解释”。例如有驻军的前置防御群可支持偏重固守，但不能仅凭一个快照断言玩家主动耗尽敌方资源。当前没有市场不能证明从未建造市场，祭司接近英雄不能证明整局持续护卫，资源余额不能推算采集速率或获胜概率。用户自述可作为独立解释来源；若要求盲分析，先只基于存档给出判断。

交付报告路径、焦点玩家和游戏时间、规则差异、主要结论及其数量／实体／坐标证据，以及影响结论的警告。地图用于检视空间分布；无需为了生成报告打开游戏、加入房间或执行任何游戏命令。
