# 本局玩家任务模板

将花括号替换为本局实际值后交给模型；未指定的策略不要猜成固定要求。

```text
请按玩家包中的 prompts/player-system.md 操作，并读取 AGENT.md、MCP.md。

连接：
  房主：{host}
  游戏 UDP 端口：{port，例20595}
  玩家昵称：{nickname，例Model-A；加入时使用nickname参数}
  本模型的独立MCP进程／连接：{客户端中的服务标识；不同参战模型使用不同进程}
  当前是否已有受控会话：{是／否／先检查}

房间规则：
  视野：{未探索迷雾／地图已探索但敌方仍受迷雾／全图公开}
  停战：{分钟数，例45}
  胜利条件：{例conquest_units，仅敌方非动物单位，建筑不计}
  对手：{人类／游戏AI／其他模型}
  初始资源与人口上限：{如已知；仍以本局公开观察核对}

本轮目标与完成证据：
  {目标1及对应可观察结果}
  {目标2及对应可观察结果}

可选技能任务（不使用的行删除）：
  附近训练：市政中心ID={id}，单位模板={template}，总数={count}。
  资源仓库：可见资源目标/位置={resource}，建造者={ids}，模板={storehouse_template}。
  空闲集结：类别={all/citizen/civilian/cavalry/champion}，目的地=({x},{z})。

限制或策略偏好：{留守、布局、保留单位/建筑、允许拆除的明确目标等}
结束后：{默认保持客户端与当前对局连接}
```

实体 ID 可在第一次 `observe_player` 后确定；如果这里尚未填写，不要用手册或上一局的 ID 补齐。用户实际房间规则优先于历史测试约定。

多个模型参战时，为每个模型提供独立的持续 MCP 进程，并使用不同昵称加入同一房间。昵称不决定席位，实际玩家 ID 以房主分配后的观察为准；`player_name` 是兼容别名，两项同时提供须相同。无需在任务中填写 session 或修改模组目录。模型共享一个服务时仍控制同一玩家，应明确命令职责。
